# japanese-nominalization-audit

[English](README.md)

`japanese-nominalization-audit` は、日本語の技術文書に含まれる過度な名詞化や、関係が分かりにくい名詞の連なりを調べるための Agent Skill を収録した Codex プラグインです。

このスキルを有効にすると、出来事、状態、条件、因果関係などを即席の複合名詞へ押し込まず、必要に応じて節として書くようエージェントに指示します。

## このスキルが行うこと

スキルが有効な間、エージェントは次のように文書を確認します。

- 新しく作られたか、まだ定着していない複合名詞、過度な名詞化、内部の関係が分かりにくい長い名詞の連なりを候補として拾います。
- 技術分野で定着している用語や、プロジェクトが定義して一貫して使っている用語は残します。
- 文脈に依存した略記や、見出しなどを埋めるために作られた語は、必要に応じて節や文へ書き換えます。
- 書き換えるときは、誰が何をしたか、何がどの状態にあるか、対象、時期、条件、否定、確実さ、因果関係を保ちます。
- 見出し、表のラベル、太字の導入部が説明を無理に名詞へ圧縮させている場合は、そのレイアウトも見直します。
- 今回追加または変更した文章だけでなく、同じ用語を使う既存の文書など、今回の変更と関係がある一次資料も確認します。
- 判断できない用語や、許可された範囲の外にある問題は、推測で変更せずに報告します。

特定の日本語訳が定まっていない技術用語は、単に原語の音をカタカナへ置き換えればよいとは考えません。原語の表記が定着している場合や、原語のほうが曖昧さを避けられる場合は、そのまま記述することも検討します。ただし、すでに定着しているカタカナの用語を一律に原語へ戻すための規則ではありません。

ソースコード、識別子、API 名、設定のキー、スキーマのフィールド、コマンド、製品名、正式な規格名、正確な引用、法的文書、固定されたインターフェースの文言は保護します。公開インターフェースの名前を変えるかどうかは、互換性を別途検討したうえで決めます。

## インストール

リポジトリを取得し、その絶対パスをローカルのマーケットプレイスとして登録してから、プラグインをインストールします。

```console
git clone https://github.com/NotLeonian/japanese-nominalization-audit.git
codex plugin marketplace add /absolute/path/to/japanese-nominalization-audit
codex plugin add japanese-nominalization-audit@japanese-nominalization-audit
```

インストールした後は、新しい Codex スレッドを開始してスキルを読み込んでください。

スキルだけを使う場合は、`SKILL.md` をローカルの Agent Skills ディレクトリへコピーします。

```console
mkdir -p "$HOME/.agents/skills/japanese-nominalization-audit"
cp /absolute/path/to/japanese-nominalization-audit/skills/japanese-nominalization-audit/SKILL.md "$HOME/.agents/skills/japanese-nominalization-audit/SKILL.md"
```

## 使い方

日本語の技術文書を作成または編集するときに、スキルを指定します。

```text
$japanese-nominalization-audit

関係する日本語の文書を確認し、分かりにくい名詞化を修正してください。
```

互換性のあるホストでは、README、仕様書、ADR、設計文書、運用手順、リリースノート、説明のためのコメントなどを対象として、このスキルが自動的に選ばれる場合もあります。

監査の対象は、現在の差分だけではありません。ユーザーが範囲を狭く指定しない限り、変更した文書に隣接する文書、共通して使う用語、テンプレート、用語集、今回の変更が影響する中心的な文書も確認します。生成物、第三者が提供する文書、保管用のスナップショット、引用は除外します。生成した文章に問題がある場合は、可能であれば生成元を修正します。

## このスキルが保証しないこと

`japanese-nominalization-audit` はエージェントへの指示であり、日本語を解析するパーサーやリンター、辞書ではありません。用語を決定する機関でも、文書が技術的に正しいことを保証する仕組みでもありません。

- 名詞化と名詞の連なりだけを対象とします。日本語全般の文体、語調、敬語、句読点、文書構成、校正、翻訳を扱う指針ではありません。
- 正規表現や検索は候補を集めるために使います。問題を見落とすことも、問題のない表現を候補として拾うこともあるため、前後の文脈を読んで判断する必要があります。
- 用語が定着しているかどうかを判断するには、プロジェクトと技術分野の根拠が必要です。リポジトリ内の一例、単一の資料で繰り返される表現、文脈のない検索結果だけでは判断できません。
- 定義や信頼できる資料が見つからない用語について、正しい判断を保証できません。その場合は、推測せずに不確実な点を報告します。
- カタカナの使用を禁じたり、常に原語で書くよう求めたりするスキルではありません。定着したカタカナの用語は残し、日本語訳が定まっていないときに根拠なく新しいカタカナ表記を作ることだけを避けます。
- プロジェクトの用語を自動的に設計し直したり、公開インターフェースの名前を変更したりしません。互換性を優先し、プロジェクトが定義している用語は残します。
- 見た目を整えることだけを目的として、保護対象のコード、識別子、引用、外部で管理される文章、法的文書、固定されたメッセージを書き換えません。
- 関係する表現をすべて発見できること、書き換えた文章が技術的に正しいこと、どの分野の読者も同じ判断をすることまでは保証しません。
- 既存の一次資料に同種の明確な問題があれば、今回の変更がほかの文書にも及ぶ場合があります。ただし、ユーザーが編集範囲を指定した場合は、その範囲を守ります。
- リポジトリ全体を確認したと報告できるのは、対象となる一次資料をリポジトリ全体にわたって実際に確認した場合だけです。
- ホストがスキルを読み込み、エージェントが指示に従っている間だけ作用します。ユーザー、IDE、別のプロセス、別のエージェント、別のセッションが行う編集は制御できません。

最後の報告には、確認した文書の範囲、この監査によって変更したファイル、節などへ書き換えた代表的な表現、意図して残した用語、解決できなかった問題、範囲外の問題を記載します。この報告は実施した確認の内容を示すものであり、ほかに問題が存在しないことを保証するものではありません。

## 構成を確認する

公開する前に JSON ファイルを検証し、Markdown とスキルの内容を確認します。

```console
python3 -m json.tool .codex-plugin/plugin.json
python3 -m json.tool .agents/plugins/marketplace.json
python3 ~/.codex/skills/.system/plugin-creator/scripts/validate_plugin.py .
git diff --check
```

プラグインの検証ツールを実行するには、Codex のシステムスキルと、それが利用する Python の依存関係が必要です。利用できない環境では省略できます。このツールは、収録しているスキルのマニフェストも確認します。

この検証で確認できるのは、プラグインとスキルの静的な構成です。エージェントの動作を再現したり、日本語の用語が定着しているかどうかを判断したり、エージェントがスキルへ正しく従うことを証明したりはしません。実際の動作を確認するときは、修正が必要な表現と、変更せずに残すべき定着した用語の両方を試してください。

## テスト

追加のパッケージをインストールせずに、リポジトリのテストを実行できます。

```console
python -B -m unittest discover -s tests -p 'test_*.py' -v
```

テストでは、JSON ファイルを解析できること、プラグインとマーケットプレイスのメタデータが一致すること、ホストがスキルを検出できる構成になっていること、`japanese-nominalization-audit` の主要な指示が残っていることを確認します。Python の検査で使う設定が正しいことと、Markdown 文書内の相対リンク先が存在することも確認します。テストの対象はリポジトリの構成と、スキルに含まれる静的な指示です。エージェントの動作は再現しないため、日本語の用語が定着しているかどうかを判断したり、エージェントがスキルに従うことを証明したりはしません。

GitHub Actions は、push と pull request のたびに、Python 3.13 を使用して Windows、macOS、Ubuntu で同じテストを実行します。

Ruff、mypy、Pyright で Python コードを検査するためのコマンドは、[CONTRIBUTING.md](CONTRIBUTING.md) に記載しています。
